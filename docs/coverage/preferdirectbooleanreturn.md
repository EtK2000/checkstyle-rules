# PreferDirectBooleanReturnCheck auto-fix coverage

Collapses an `if` whose body and paired return (else branch or next sibling) are each a single boolean return.

Opposite literals -> `return cond;` / `return !cond;` (multi-line conditions joined; `//` comments relocated; a parenthesized literal like `return (true);` is recognized; a multi-token negation wraps as `!(...)`).

Both branches the same literal -> `return LIT;`: the condition is dropped when it is side-effect-free (dropped even if it could throw, e.g. `flags[i]`, `a / b`, a pure cast `(boolean) obj`, or a field dereference); when it has a hoistable side effect that effect is extracted ahead of the return, for a whole statement-expression (`if (compute()) ...` -> `compute();`; `found = a > b` -> `found = a > b;`), a comparison wrapping one (`++i > 0` / `i++ > 0` -> `++i;`, a postfix operand normalized to prefix since its value is discarded; `(x <<= 1) > 0` -> `x <<= 1;`), or an `&&` whose value is discarded (`pure && stmtExpr` -> `if (pure) stmtExpr;`; `stmtExpr && pure` -> `stmtExpr;`; `stmtExpr && stmtExpr` -> `if (left) right;`). A leading cast is transparent: it is classified by the operand it wraps, so a cast over a side effect drops the cast (with its `ClassCastException` risk, like the pure-cast drop) and hoists the operand (`(boolean) box()` -> `box();`). A comparison with both operands side-effecting, or a `||` (which would need an introduced negation), is left alone.

One non-literal branch collapses via short-circuit (`C && X` / `!C || X` / `C || X` / `!C && X`) with precedence-minimal parens, unless the non-literal return spans more than one line, the collapse mixes `&&` with `||`, uses three or more boolean operators, or would exceed the max line length.

Not fixed when the `if` condition spans multiple lines (never closes, or crosses a text block / block comment) or contains a `\u` unicode escape, nor when a same-literal condition's side effect sits across a tight (unspaced) `<`/`>` comparison that text cannot distinguish from a generic type argument (`m()>0` is skipped, while the spaced `m() > 0` extracts), or across more than one comparison (a chained `a < b == c`, which cannot be split at the top-level operator without precedence parsing). It also skips (reporting a reason) on irregular layout a text fixer cannot safely rewrite: the then-body is not a single collapsible return (`if body is not a simple collapsible return` -- a mis-indented or truncated braced body, or an absent/mis-indented next-line body); a `//` comment sits between the condition's close paren and the body (`comment between condition and body`); or there is no adjacent else/trailing return in the expected single-return form (`no simple collapsible else or trailing return` -- a blank line before it, a mis-indented trailing return, or a mismatched/truncated else brace). A both-non-literal ternary is left alone.
