# PreferDirectBooleanReturnCheck auto-fix coverage

Collapses an `if` whose body and paired return (else branch or next sibling) are each a single boolean return.

Opposite literals -> `return cond;` / `return !cond;` (multi-line conditions joined; `//` comments relocated; a parenthesized literal like `return (true);` is recognized; a condition that is a bare name, a dotted chain, a call on one or an already-parenthesized group takes a bare `!`, while anything else wraps as `!(...)`, which covers an operator outside parentheses but also an array index (`flags[i]`) or a call on a literal (`"x".equals(s)`), and a parenthesis inside a literal or a comment neither forces nor suppresses the wrap; a leading `!` over a condition of the first kind is dropped instead of doubled).

Both branches the same literal -> `return LIT;`: the condition is dropped when it is side-effect-free (dropped even if it could throw, e.g. `flags[i]`, `a / b`, a pure cast `(boolean) obj`, or a field dereference); when it has a hoistable side effect that effect is extracted ahead of the return, for a whole statement-expression (`if (compute()) ...` -> `compute();`; `found = a > b` -> `found = a > b;`), a comparison wrapping one (`++i > 0` / `i++ > 0` -> `++i;`, a postfix operand normalized to prefix since its value is discarded; `(x <<= 1) > 0` -> `x <<= 1;`), or an `&&` whose value is discarded (`pure && stmtExpr` -> `if (pure) stmtExpr;`; `stmtExpr && pure` -> `stmtExpr;`; `stmtExpr && stmtExpr` -> `if (left) right;`). A leading cast is transparent: it is classified by the operand it wraps, so a cast over a side effect drops the cast (with its `ClassCastException` risk, like the pure-cast drop) and hoists the operand (`(boolean) box()` -> `box();`). A comparison with both operands side-effecting, or a `||` (which would need an introduced negation), is left alone.

Hoisting is the one collapse that emits more than one statement, so it is also the one that can need a block. When the `if` is itself the unbraced body of an enclosing `if`, `else`, `for`, for-each, `while`, `do` or labelled statement, that slot holds a single statement, and every statement the hoist emits (the retained guard `if` when there is one, the hoisted effect, and the return) is wrapped in `{ }` so all of them stay inside the enclosing statement. Nothing is wrapped under a statement list, an unbraced `case` group included. The block opens on the enclosing header's line when the `if` shares it (`if (flag) {`), and on its own line at the body's indentation otherwise. The extra indentation counts toward the line-length budget, so a hoist that fits under a braced parent can be refused under an unbraced one. A collapse that emits a single statement is never wrapped, whatever the parent.

One non-literal branch collapses via short-circuit (`C && X` / `!C || X` / `C || X` / `!C && X`) with precedence-minimal parens, unless the non-literal return spans more than one line, the collapse mixes `&&` with `||`, uses three or more boolean operators, or would exceed the max line length. The `!C` of the two negated forms is written exactly as in the opposite form.

Comments inside the replaced span are kept. A block comment written inside the condition or inside a re-emitted non-literal return travels with that text (`if (/* c */ flag)` -> `return /* c */ flag;`); every other comment in the span moves to one trailing `//` on the collapsed line, in source order, including a `//` anywhere in the condition (which would otherwise comment out the rest of the collapsed line), one between the `if` and its `(`, one after the close paren, one inside a braced body on either side of the return, one on the then-block's `}` or on the `else` line, and one trailing either return. The one exception:
when the text left on the collapsed line after the span leaves a block comment or a text block open,
the relocated comment is dropped instead, because appending it there would be swallowed by that
comment or would not compile.

Fixer refusals, each reported with its reason:

| Reason | Shape |
|---|---|
| `cannot collapse the if: it would destroy a text block's significant whitespace` | a text block inside a condition the collapse re-emits, or inside a hoisted side effect or the guard it keeps. A side-effect-free same-literal condition is dropped whole, so a text block in it collapses normally |
| `cannot collapse the if: it would fold a class body onto one line` | a multi-line anonymous or local class in any of those three places; folded onto one line its members and annotations land there too, which the project's own formatting rules reject. A class body already written on one line is collapsed normally |

Check-level refusals, which report nothing at all: both branches non-literal (a ternary); a same-literal condition whose side effect fits none of the three hoistable shapes, including a `||` (which would need an introduced negation) and a comparison with both operands side-effecting; and, for the short-circuit form only, a non-literal return value spanning more than one line or a join that would mix `&&` with `||` or use three or more boolean operators.

One refusal applies to all three forms: a collapse any of whose emitted lines would exceed the max line length. The budget is measured on the emitted text, so interior whitespace, a comment kept inline, and any code the replaced span leaves on its closing line all count toward it. The relocated trailing comment is the one exclusion, since a long comment would otherwise suppress the violation outright.

Also handled: no space after `if`; a comment between `if` and `(`; a comment after the close paren, inside a braced body, on a `}` or `else` line, or trailing a return as a block comment; a block comment inside a boolean-literal return (`return /* c */ true;`); a `\u` escape in a parseable condition; a tight (unspaced) `<`/`>` comparison; a chained comparison; generics whose angle brackets do not balance at depth 0; a mismatched close brace or trailing-return indent; a blank line before the trailing return; more than one statement on the `if` line; and code before the `if` or after the paired return on its line.
