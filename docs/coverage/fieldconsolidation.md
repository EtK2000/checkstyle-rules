# FieldConsolidationFixer auto-fix coverage

Line-length wrapping measures tab-expanded length at tab-width 4, with a 120-character threshold.
Continuation lines use base indent + 2 tabs.

| Scenario | Behavior | Reason |
| --- | --- | --- |
| Line length at a different tab width | May wrap too early or too late | Wrapping uses a fixed tab-width of 4; projects displaying tabs as 8 will see wider lines than the fixer expects |
| Violation column does not point at an identifier start | Scans forward to the next identifier | Tolerates intra-line shifts from a sibling fixer (e.g. `ArrayTypeStyleFixer` rewriting `int x[]` to `int[] x` before this fixer runs) |
| Violation column lands mid-identifier (not at a name start) | Skipped | A sibling fixer (e.g. `FieldSortingFixer`) reflowed this group into a wrapped declaration earlier in the same pass, so the violation is stale; acting on it would truncate the name. Defers to the next pass |
| Recovered column has advanced past the violation's `;` | Skipped | The identifier found is a different declaration, not this fixer's target |
| Non-BMP (supplementary code point) content ahead of the field name | Handled | The reported column counts code points and is converted to a char index before any slicing; the identifier-boundary scans still use the `char` overload, so a supplementary code point *inside* an identifier may still be misclassified |
| Previous field's declaration carries a multi-line literal (text block in an annotation argument, or block comment) | Skipped | A `;`/`,` inside the text-block or block-comment interior is not mistaken for a field terminator; if the prev field's declaration genuinely spans multiple lines, merging would strand the opener, so it is skipped |
| Field declaration whose type wraps across lines (a generic type split over lines, e.g. `Map<String,` / `Integer> f;`) | Skipped (`cannot consolidate a field whose declaration spans multiple lines`) | The line-based type extraction reads a single physical line; an unbalanced `<`/`>` on the previous field's prefix (or before the violation field's name) signals a wrapped type whose merge would mangle it (dropping `Integer>`), so the fixer skips |
| Continuation line of a multi-variable declaration begins inside a carried block comment | Skipped (`cannot consolidate when a declaration line carries content after its terminator`) | The continuation scan tests each line textually (`isCommentLine`) and does **not** consult the carried lexer state, so such a line is read as a field name. The refusal comes later, from the intermediate-comment scan over `[prev, endLine]`, which sees the comment marker and refuses rather than delete it. Pinned by `continuation_inside_carried_block_comment_bails` |
| Preceding same-type field's declaration line cannot be located (backward line-scan obscured by a carried text block / comment, or no field precedes) | Skipped (`could not locate the preceding field declaration`) | The line-based backward scan can't identify where the previous field starts, so the merge target is unknown and merging is unsafe |
| Block comment on the violation's field declaration line (before the name, or between the name and its `;`/`,`) | Skipped (`block comment on the field declaration line`) | A block comment sharing the declaration line can hide a `;`/`,` or the name from the line-based scan; merging risks mis-parsing, so the fixer defers |
| Previous field's declarator list carries different C-style brackets per name (`int alpha, beta[];`) | Skipped (`cannot consolidate a declaration whose declarators carry different array brackets`) | The merge renders one base type plus bare names, so the brackets have to be hoisted onto the type; hoisting one declarator's brackets would retype its siblings. `FieldConsolidationCheck` no longer reports such a pair, so this only guards a buffer a sibling fixer reshaped mid-pass |
| Previous field's declaration wraps, so its names start the line and its type sits above (`int` / `alpha[];`) | Skipped (same reason) | There is no base type on the previous field's line to hoist the C-style brackets onto |
| Only the violation's line carries a trailing comment (`int alpha;` / `int beta; /* note */`) | Merged, comment carried onto the surviving terminator | The merge keeps one terminator and one tail; a lone comment from the consumed line is re-emitted after the surviving `;` rather than dropped |
| Both declaration lines carry trailing content, the consumed line's tail is not a self-closing comment (code after the `;`, or a block comment left open), or an intermediate continuation line carries a comment | Skipped (`cannot consolidate when a declaration line carries content after its terminator`) | Only one tail survives the merge: dropping a second comment would re-attribute the survivor to both fields, and dropping code would delete it outright |
