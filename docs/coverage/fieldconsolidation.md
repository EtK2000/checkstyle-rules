# FieldConsolidationFixer auto-fix coverage

The fixer folds the whole run around a violation into its first declaration in one rewrite. Line-length wrapping measures tab-expanded length at tab-width 4, with a
120-character threshold. Continuation lines use base indent + 2 tabs.

| Scenario | Behavior | Reason |
| --- | --- | --- |
| Line length at a different tab width | May wrap too early or too late | Wrapping uses a fixed tab-width of 4; projects displaying tabs as 8 will see wider lines than the fixer expects |
| Same-key declarations with fields of another type, visibility or modifier set, a declaration with a long initializer, or blank lines, between them (`int alpha;` / `String label;` / `int beta;`, `private int alpha;` / `public int beta;` / `private int gamma;`, `int alpha;` / `volatile int beta;` / `int gamma;`, `int alpha;` / `int beta = 1_000_000 + 2_000_000 + 3_000_000;` / `int gamma;`) | Merged into the first (`int alpha, beta;` / `String label;`) | A run is every declaration of one key in a stretch of fields; the fields between keep their place. Two runs interleaved in one stretch (`int alpha;` / `String first;` / `int beta;` / `String second;`) each merge, all in one rewrite from any of their events, so no later pass is needed for the others. A run that cannot be merged (a moved comment spanning lines, a tool directive) is left as written while the runs around it merge. When the rewrite folding them all would fail the check described below, only the run of the reported event is merged and the others are left as written |
| A type annotated `@SuppressWarnings("FieldSorting")` | Merged in source order: names are not sorted, and only declarations with no other field between them merge, blank lines allowed (`int beta;` / `int alpha;` becomes `int beta, alpha;`; `int alpha;` / `String label;` / `int beta;` is not reported, and neither is `int alpha;` / `int beta = <long>;` / `int gamma;`) | FieldSorting leaves such a type's fields as written, so the merge neither reorders names nor moves a declaration past another field. A nested type without the annotation is sorted as usual |
| A class body where the `suppressions.xml` suppresses FieldSorting on any line | The fix merges in source order, as for the annotation above | The checkstyle run never sorts those fields, so a merge must not either. The check itself cannot see the suppressions, so it still reports a pair with another field between them, which the fix then leaves as written (`cannot consolidate: the declaration was already merged earlier in this pass`) |
| A comment switching a tool off or on for the lines after it, or counting lines, on a line of the run: from its first declaration to its last one's `;`, trailing a field of another key between them included (`String header; // CHECKSTYLE:OFF` / `int alpha = 7;` / `long footer; // CHECKSTYLE:ON` / `int beta = 42;`; also `@formatter:off`/`on`, `spotless:off`/`on`, `CHECKSTYLE.OFF`/`ON`, a folding region marker such as `//region Tuning` or `//#endregion`, or either one alone); or a Checkstyle suppression comment counting lines (`// CHECKSTYLE IGNORE MagicNumber FOR NEXT 3 LINES`) whose count reaches a line of one of the run's declarations, from wherever it sits (above a directive-led first field, trailing a field of another key) | Skipped (`cannot consolidate: a comment around the fields switches a tool off or on for the lines after it or counts lines, and the merge would move names into or out of its reach`) | The merge moves later names onto the first declaration's line and removes their lines, so a name would move into or out of the switched-off lines or the counted ones. One past the run's last `;` (`long footer; // CHECKSTYLE:OFF` below the run) and a count ending before the run's lines (`// CHECKSTYLE IGNORE MagicNumber FOR NEXT 1 LINES` above a directive-led `int alpha = 1;`, with `int beta = 2;` / `int gamma = 3;` below) leave it alone, and the merge goes ahead |
| A comment that has to move is a tool directive acting on its own line (`NOSONAR`, `NOPMD`, `$NON-NLS-`, `CHECKSTYLE`, `language=`, `noinspection`; `int beta; // NOSONAR`) | Skipped (`cannot consolidate: a comment that has to move above the merged declaration is a tool directive acting on its own line`) | Moved onto a line of its own, it would stop covering the declaration it was written for. A directive the merged declaration keeps on a line of its own (the first declaration's own annotation line) does not move and does not block the merge, and neither does a moved one that a kept comment repeats word for word. The match is case-sensitive |
| A tool directive the merge would keep on a line it then shares with other names: trailing the first declaration (`int alpha; // NOSONAR` above `int beta;`, even when `int beta; // NOSONAR` repeats it), ahead of the first declaration's type or among or inside its names on the line the later names join (`/* NOSONAR */ int alpha;`, `int alpha, /* NOSONAR */ beta;`, `int alpha = /* NOSONAR */ 1;` above `int beta;`), or inside a declarator that is rebuilt next to others (`int beta = /* NOSONAR */ 1;`, or `int zeta = /* NOSONAR */ 1;` once `alpha` sorts ahead of it) | Skipped (`cannot consolidate: a tool directive acting on its own line would end up on a line holding names it was not written for`) | A directive acting on its line would then cover every name merged onto that line too |
| A tool directive leading a declaration: a statement-scoped one (`//noinspection unused` above `int alpha;`, with `int beta;` below) wherever it leads it, other comments or blank lines between them included (`//noinspection unused` / `/* legacy` / ` */ int alpha;`), trailing the line above (`String label; //noinspection unused`) or on an annotation line (`@Deprecated //noinspection unused`); or any other on a line of its own, above it or between its annotations and its type (`// CHECKSTYLE IGNORE MagicNumber FOR NEXT 1 LINES`, `// language=SQL`, `@Nullable` / `// NOSONAR` / `private String alpha;`), or starting on one and spanning lines, closing on the name's line at the latest (`/* CHECKSTYLE IGNORE MagicNumber FOR NEXT 1 LINES` / ` */ private int a = 7;`) | Not reported: the declaration joins no run, while the others of its key still merge past it (`//noinspection unused` / `int alpha;` / `int beta;` / `int gamma;` becomes `int beta, gamma;` below `int alpha;`) | The directive may act on the declaration or lines after it, so it would widen to merged names. FieldSorting applies the same rule, so neither fixer merges into such a declaration. A directive ahead of the first declaration's type on the name's line (`/* NOSONAR */ int alpha;`) acts on that line and is the row on directives the merge would widen, and one ahead of an annotation on its line (`/* NOSONAR */ @Deprecated`) acts on that line and leads nothing; one trailing the line above or an annotation line, other than a `//noinspection` (`String label; // NOSONAR`), acts on that line, and one above code that ends before the declaration (`//noinspection unused` / `String label;` / `int alpha;`) leads that code, so the merge goes ahead. The match is case-sensitive; `// NoInspection` and `// Language=SQL` are plain comments and the merge goes ahead, the comment staying above it |
| A field read, while its declaration initializes, by an earlier field's initializer: through `this.`, or through `Outer.this.` or the class's own name where `Outer` spells that class itself (simply, through its enclosing types or through its package), assigned (`int a = (b = 5) + 1;`), or from a lambda body or an anonymous class body's initializers (`int total = this.count * 2;` above `int count = 3;`) | Not reported against a run starting at or above the reader, nor when the reader is inside the run; a declaration holding both names joins no run | The reader sees the field's default until its declaration runs, so moving the field to or above it would change what the reader computes (`total` from 0 to 6). A run starting below the reader still merges (`long total = this.count * 2L;` / `int base;` / `int count = 3;` becomes `int base, count = 3;`). A lambda counts because one called while initializing (a stream's `map`) runs then. Reads of a field with no initializer or of a constant variable (`final` primitive or `String`, `java.lang.String` too, initialized from literals) read the same either way and do not count. A member of another object or type (`other.count`, `super.count`, `Integer.MAX_VALUE`, `Adapter.this.count` of an enclosing class), a method name (`items.size()` beside a later `size`), a type's, an annotation's or a label's name, a whole `case` label, and a name the initializer binds itself where its scope does not depend on a test (a lambda parameter, a method or constructor parameter of a local class, a local declared earlier in a block, `final var label = "x";` in an anonymous class body's initializer block beside a later runtime `label`, a for, catch or resource variable inside its statement) are no read of the later field. A pattern variable named like the field counts as a read of it only inside an anonymous class body; read directly by the initializer or inside a lambda it is a bare name, so it does not count and the merge goes ahead (`long t = o instanceof Long c ? c : 0;` / `long c = 3;` becomes `long t = o instanceof Long c ? c : 0, c = 3;`). What a called method reads is not traced; the call pins the field instead (see the next row). A bare name read ahead of its declaration does not compile, so it is not considered |
| A declaration that would move past a field it may not trade places with (pinned): one of them may observe the order while initializing (anything but literals, operators, parentheses, casts and array creation, as FieldSorting's row on pinned fields lists: any read, any call or `new` of a non-array, JDK ones such as `String.valueOf(1)` included, a lambda, a write such as `++issued`, `this` handed out) and the other is not inert (it has an initializer and is no constant variable) | Not reported | `int base = 10;` / `String report = new Report().text();` / `int max = 100;`: `report` may read `max` through the inner class, so `max` keeps its place below it, and `String label = String.valueOf(1);` holds it the same way. An inert field still merges past it (`int base;` / `String report = ...;` / `int max;` becomes `int base, max;`), and so does any field past fields built from literals alone (`String label = "none";`) |
| Pinned names in one run (`int zeta = Ids.next();` / `int alpha = Ids.next();`) | Merged in source order (`int zeta = Ids.next(), alpha = Ids.next();`) | Swapping them would swap the ids each gets. A name pinned to an earlier one waits for it as a reader waits for what it reads, so the rest still sort (`int zeta = Ids.next();` / `int mid;` / `int alpha = 2;` becomes `int mid, zeta = Ids.next(), alpha = 2;`) |
| A merge, folded runs included, that would move a field past one it may not trade places with, found by the re-parse | Skipped (`cannot consolidate: the merge would move a field past another field whose initializer runs code or reads it, which could change the value read or written`) | A fold of interleaved runs that would do so falls back to the run of the reported event alone |
| A constant: a field with a value written `static final` (in any modifier order, with any other modifiers or annotations), or any field of an interface or annotation type (`static final Object LOCK = new Object();`, `interface I { int A = 1; }`) | Not reported and never merged, on its own line or already merged by hand | Constants read as well one per line as merged, so neither is a style error. A constant does not end the stretch: the fields of its key around it still merge past it (`static int alpha;` / `static final int LIMIT = 5;` / `static int gamma;` becomes `static int alpha, gamma;` / `static final int LIMIT = 5;`), unless the move is refused for another reason. `static final int A;` with no value, an instance `final int a = 1;`, and the fields of a class nested in an interface are no constants |
| A line holding only a comment, or any other member (a method, a constructor, an initializer, a nested type, a stray `;`), between them | Not reported | Either ends the stretch of fields. A comment-only line is taken to describe what follows it |
| A `final` declaration with a value and one without (`final int alpha = 1;` / `final int beta;`) | Not reported | FieldSorting keeps finals with an inline value apart from finals without, so each kind forms its own run (`final int alpha = 1, gamma = 2;` / `final int beta, delta;`) |
| An anonymous-class field, or one reading one directly or through other fields, and a field doing neither (`final Object first = new Object() {};` / `final Object plain = "p";`) | Not reported | FieldSorting places those by the anonymous-class fields they hold or read, so the two kinds form separate runs, each of which still merges |
| A declaration whose merge would move it past a field it reads, or one that reads it (`int alpha = 1;` / `String label = "v" + alpha;` / `int beta = label.length();`) | Not reported against the run before it | It starts a run of its own, which later declarations of its key can join (`int beta = label.length(), gamma;`) |
| Short initializers, on any declarator: the name and the value together come to at most 30 code points (`int alpha = 1;` / `int beta;`, `String s = "123456789012345678901234567";`, `Object o = new Object() {};`). The value is everything between `=` and the `,` or `;` after it, trimmed, counted as written: comments (`1 /* c */ + 2`), escapes (`"\n"` is 2) and underscores count, C-style brackets after the name and the spaces around `=` do not. A declarator with no initializer is always short, whatever its name's length | Merged | A declarator keeps its initializer and the comments inside it as written |
| A long initializer: over 30 code points with its name (`int beta = 1_000_000 + 2_000_000 + 3_000_000;`, `String s = "1234567890123456789012345678";`), on any name of a declaration (`int beta = <long>, gamma;`), including a declaration already written with several long names (`int alpha = <long>, beta = <long>;`) | Not reported, never merged | A long value hides the other names sharing its line, so such a declaration stays on its own. A whole declaration is kept apart when any of its names is long. It does not end the stretch of fields: the short declarations of its key around it still merge past it (`int alpha;` / `int beta = <long>;` / `int gamma;` becomes `int alpha, gamma;` / `int beta = <long>;`), its comments and tool directives staying where they are, unless the move is refused for another reason (a field it reads or that reads it, a read at initialization, a pinned field) |
| A declarator spanning lines that fits on one (`int beta =` / `12;`, `int beta` / `= 10;`, `String beta = "60"` / `.trim();`, `int beta = 1 > 0` / `? 1` / `: 2;`, `int[] beta = {` / `1, 2` / `};`, `Object beta = new Object() {` / `};`, `Runnable beta = () -> {` / `};`) | Measured, and merged, as that one line (`beta = 12`, `beta = "60".trim()`, `beta = {1, 2}`, `beta = new Object() {}`), on the first declaration too (`int alpha =` / `12;` / `int beta;` becomes `int alpha = 12, beta;`) | Its lines are joined with a single space, none after `(`, `[` or `{` or before `.`, `)`, `]`, `}`, `,` or `;` |
| A declarator with no initializer spanning lines (`String first // note` / `;`, `int alpha, beta // note` / `;`) | Short, so merged, the comment moved above (`// note` / `String first, second;`) | With no value, nothing is hidden by the names sharing its line. The `;` joins the last name, so the first declaration is rebuilt from its first name on, as when a name spans lines |
| An initializer spanning lines that cannot fit on one: a comment anywhere from its name on (`int beta = 1 // c` / `+ 2;`, `int beta = 1 /* c */` / `+ 2;`), a text block, or a line break inside a class body, block or switch that holds something (`new Object() {` / `int counter;` / `}`, `() -> {` / `System.gc();` / `}`, `switch (alpha) {` / `default -> 1;` / `}`) | Long, so not reported and never merged | Joining it would comment out code, change a text block, or fold a body onto one line. A body that sits on one line already (`Runnable beta =` / `() -> { System.gc(); };`) does not count, and neither does an empty one (`new Object() {` / `}` joins as `new Object() {}`) |
| Whitespace inside a one-line declarator: none or several spaces or tabs around `=` (`int beta=5;`, `int beta  =  5;`, `int beta` + tab + `=` + tab + `5;`), on the first declaration or a later one | Merged as written (`int alpha, beta=5;`, `int alpha  =  5, beta;`) | A declarator is carried over as written; spacing is not this fixer's concern |
| Whitespace or a line break before a declaration's `;` (`int beta = 5 ;`, `int beta = 5` / `;`, `int beta` / `;`), or a line break before a `,` (`int alpha = 1` / `, beta = 2;`) | Merged without it (`int alpha, beta = 5;`, `int alpha = 1, beta = 2, gamma;`) | The declarator's text ends at its last token; a name whose `,` or `;` is on a later line has the first declaration rebuilt from its first name on |
| A later declaration broken anywhere (`int` / `beta = 5;`, `int beta` / `= 5;`, `int` / `beta` / `=` / `5` / `;`) | Merged onto the merged declaration's line (`int alpha, beta = 5;`) | Only a later declaration's declarators are carried over, each joined onto one line |
| The first declaration broken after its type (`int` / `alpha = 5;`, `int` / `alpha` / `=` / `5` / `;`) | Merged, the break after the type kept (`int` / `alpha = 5, beta;`) | The part ahead of the first name is kept as written (as for a wrapped type); the rest is joined |
| The first declaration's names already wrapped after a `,` (`int alpha = 1,` / `beta = 2;` above `int gamma;`) | Merged, its lines kept as written (`int alpha = 1,` / `beta = 2, gamma;`) | When its names stay in order, the first declaration is kept as written up to its `;` |
| Name order in the merged declaration | Sorted as FieldSorting orders one declaration's names: by name, each after the names it reads and the earlier names it is pinned to (`int zeta = 1;` / `int mid;` / `int alpha = zeta;` becomes `int mid, zeta = 1, alpha = zeta;`) | The merge then needs no FieldSorting pass. Names that read each other in a cycle keep their source order |
| The first declaration's comments | Kept. Its trailing comment stays trailing (`int alpha, zeta; // why zeta`); any comment ahead of its first name stays where it is | When the names are reordered, the first declaration is kept only up to its first name, so a comment between its own names moves like any other below |
| Any other comment of the run: ahead of a later declaration, on its annotation line, among its declarators or trailing it (`int beta; /* why */`, `@Deprecated // why`) | Moved above the merged declaration, all joined into one line comment in source order (`// why beta why gamma`); one repeating a comment the merged declaration keeps, or another moved one, is dropped | One line comment cannot be misread as belonging to a single name. A comment holding `*/` or `//` joins as written (`// ends */ here`) |
| A comment that has to move spans several lines (`int alpha,` / `/*` / ` * note` / ` */` / `beta;` below `int prevName;`) | Skipped (`cannot consolidate: a comment that has to move above the merged declaration spans several lines`) | Joining it into a line comment would reflow its text. The whole run is skipped, never merged in part |
| A block comment opening on another field's line and closing on a later declaration's line (`int alpha;` / `long zulu; /* c` / `*/ int beta;`) | Skipped (`cannot consolidate: a comment that has to move above the merged declaration spans several lines`) | The later declaration's line leaves with the merge, which would take the comment's `*/` with it |
| Comments to move, when the first declaration's line opens inside a block comment from an earlier line (`/* legacy` / ` */ int alpha;` above `int /* moved */ beta;`), through any chain of such comments (`/* first` / ` */ /* legacy` / ` */ int alpha;`) or behind other comments on that line (`/* note */ /* legacy`) | Merged, the moved comments put above the line the first comment opens on (`// moved` / `/* legacy` / ` */ int alpha, beta;`) | Put on the declaration's own line, they would land inside the block comment |
| The same, when code sits ahead of that block comment on its line (`char zulu = 'z'; /* legacy` / ` */ int alpha;`), at any step of the chain | Skipped (`cannot consolidate: the merged declaration opens inside a block comment that starts after other code, leaving the comments that have to move no line of their own above it`) | Above that line they would sit over another field |
| Other code shares a declaration's first line ahead of it or its last line after it (`int beta; int gamma;`, `String s = "x"; int zebra;`) | Not reported | The merge rewrites whole lines, so it would carry the code off |
| The first declaration's type or annotations wrap across lines (`int` / `alpha[];`, `Map<String,` / `Integer> f;`, a multi-line annotation) | Merged, the wrapped part kept as written (`int[]` / `alpha, beta;`) | Only the text from its first name on is rebuilt |
| C-style brackets on the first declaration's names (`int alpha[];` / `int[] beta;`) | Merged with the brackets moved onto the type (`int[] alpha, beta;`) | The run shares one normalized type, so the later declarators' own brackets are dropped |
| The event's column does not point at the field's name (a sibling fixer moved it along its line), or lies outside the line | Handled | The field named on the event's line nearest the column is taken |
| An event on a declaration that is the first of its run, or that a merge earlier in the pass already folded in | Skipped (`cannot consolidate: the declaration was already merged earlier in this pass`) | The run it belonged to has been rewritten; the next pass re-runs the check. An event on a line holding no field is not fixable |
| File starting with a byte-order mark | Handled | The mark is kept ahead of the first line |
| Non-BMP (supplementary code point) content ahead of or inside a field name | Handled | |
| A run of thousands of declarations | One rewrite | A 2,000-declaration run, plain, each reading the one before, or each with a trailing comment, folds in one call |
| Any other rewrite that would not reproduce the original fields, comments and surrounding code | Skipped (`cannot consolidate: the merge would change a field, a comment or the code around them`) | Every field must keep its name, modifiers, annotations, type and initializer; a Javadoc must stay on a declaration of exactly the same names; any other comment must stay on the declaration that ends up holding the field it trails or leads, where two identical ones may become one and the moved ones may become exactly their join; and nothing outside the fields may change |
| An annotation nested past 50 levels anywhere in the file, even on a member the merge does not touch, or a unicode escape anywhere in the file that javac decodes into a quote, a backslash, a comment delimiter or a line break (`// \u000a ...`, `"a\u0022 + \u0022b"`) | Skipped (same reason) | Past the cap an annotation's identity is unknown. javac decodes escapes before it reads literals and comments and the parse does not, so the two end them in different places and the file cannot be shown unchanged. An escape after an escaped backslash (`"\\u0022"`) is not decoded and does not count |
| Either declaration has a doc comment (`/**`, `/***/` or a `///` line comment, not `/**/`) whose next token is the declaration's first token: above it (across blank lines and other comments), trailing the line above (`int zeta; /**< doc */` over `int alpha;`), or ahead of its first token on its own line (`/** px */ int alpha;`) | Not reported | javac gives a doc comment, `@deprecated` included, to every name of the declaration whose first token follows it, whatever code sits before it on its line. The merge keeps one declaration's prefix for every name, so it would stretch the comment over the names it brings in, or leave it to document whatever follows. A doc comment with another token next (`private /** d */ int alpha;`, `int alpha /** d */;`, or `/** d */` after `@Deprecated`) documents nothing, so the pair is reported and merged. On the first declaration such a comment stays where it is; on a later one it moves like any other (`// d`) |
| Annotations that are one type spelled two ways, or two types sharing a simple name (`@Deprecated` and `@java.lang.Deprecated`, `@javax.annotation.Nullable` and `@org.jetbrains.annotations.Nullable`), at any position: on the field, nested in an annotation value, or type-use | Not reported | The merge keeps one declaration's annotations for both, so they are compared by the name as written; telling two spellings of one type apart would need import resolution |
| A repeated annotation in a different order (`@Tag("x") @Tag("y")` against `@Tag("y") @Tag("x")`) | Not reported | Its container keeps the source order. Distinct annotations in a different order (`@A @B` against `@B @A`) are still reported |
| Stacked type-use annotations on one level in a different order (`String @A @B []` against `String @B @A []`) | Not reported | Type-use annotations are compared in source order |
| Modifier keywords written in a different order (`private static int alpha;` above `static private int beta;`) | Merged (`private static int alpha, beta;`) | Modifiers are compared as a set, and the kept prefix is the previous declaration's |
| Annotations nested past 50 levels | Not reported | What lies below the cap is unknown, so the two cannot be shown equal |
| A stray `;` between the two fields (`int alpha;;` above `int beta;`) | Not reported | The `;` is a member of its own that keeps them apart, as a method would |
| C-style declarator brackets on a field whose type, or whose own brackets, carry a dimension annotation (`int alpha @A [];`, `int @A [] alpha[];`) | Not reported | Declarator brackets are the outer dimensions (JLS 10.2), so where the brackets were written decides which level an annotation is on. The check does not compare such a type at all, so `int @A [] alpha[];` above `int[] @A [] beta;` stays unmerged even though both are `int[] @A []` |
| A wrapped annotation on a later declaration (`@Size(min = 1,` / `max = 10) String beta;`), or a later declaration spread over several lines (`int b,` / `c /* x */;`) | Merged | Only its declarators are carried over; the annotation is the first declaration's, which the key makes equal. A comment among them moves above (`// x` / `int a, b, c;`). A declarator with an initializer spanning lines follows the short-initializer rows above |
| A comment among the first declaration's names, between a name and its `;`, or after C-style brackets that move (`int alpha[], /* legacy */ beta[];`, `int alpha[] /* legacy */;`) | Merged, the comment moved above (`// legacy` / `int[] alpha, beta;`) | Rebuilding the declarators leaves no place for it. One ahead of the type (`/* legacy */ int alpha[];`) or after a name whose text is kept (`int alpha /* [] */;`) stays where it is (`/* legacy */ int[] alpha, beta;`, `int alpha /* [] */, beta;`) |
| Two identical comments, trailing or moved (`int alpha; // px` / `int beta; // px`) | Merged, kept once (`int alpha, beta; // px`) | Repeating it would say the same thing twice |
