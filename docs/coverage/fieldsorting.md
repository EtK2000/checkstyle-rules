# FieldSortingCheck auto-fix coverage

The fixer parses field declarations in a class body and sorts them by the check's rules.
Enum constant sorting is handled separately (see main table).

| Violation type | Pattern | Auto-fix | Notes |
| --- | --- | --- | --- |
| Chunk order | Non-final before final-with-value | Yes | Adds blank lines between chunks |
| Type order (prim vs ref) | `String name` before `int count` | Yes | Primitives sort before reference types |
| Type order (alphabetical) | `String` before `int` (same chunk) | Yes | Alphabetical by base type name |
| Array depth | `int[]` before `int` | Yes | Base type first, then arrays |
| C-style array declarator | `int elements[];` after `int codes;` | Yes | The declaration moves as whole lines. It is never merged into a same-type sibling nor rebuilt from its names, either of which would drop the per-declarator `[]` and silently retype that declarator |
| Annotation order | `@Nullable String` before `@NonNull String` | Yes | Unannotated first, then by canonical annotation key |
| Type-arg annotation order | `List<@B String>` before `List<@A String>` | Yes | Position-aware: compares type arguments left to right, unannotated before annotated, then alphabetical. Extracts annotations from `<...>` in the captured type name |
| Annotation consolidation | Same-type same-annotation fields on separate lines | Yes | Merges into single declaration after sorting |
| Name order | `int z` before `int a` (same type) | Yes | Case-insensitive alphabetical |
| Name order (within declaration) | `String zebra, alpha;` (one multi-name decl) | Yes | Reorders names in place (case-insensitive). Single-line, wrapped, and trailing-comment forms. The declaration's own line is located from the AST, so a declaration that starts on a line opening with an annotation (`@Deprecated private int y, x;`) or sits below a multi-line annotation is rebuilt in place instead of being emitted twice. See the skip rows below for the interior-comment and initialized forms |
| Interleaved opposite-static field | `int zebra;` `static int x;` `int alpha;` | Yes | Same-group fields are swapped into their existing physical slots; the interleaved opposite-static field stays put |
| Interleaved group spanning chunks or with dependencies | an interleaved reorder whose group is not a single dependency-free chunk | No | The in-place slot swap can't safely rebuild it; the fixer returns a `SkipResult` (`cannot reorder fields across an interleaved static or instance field`) |
| Same-line enum constant with annotation | `@Deprecated BETA, ALPHA` | Yes | Each constant is emitted from its own AST span, with its annotations relocated above it one per line. A constant or comment sharing the annotation's first or last line is attributed to exactly one owner, so neither is duplicated or dropped |
| Same-line enum constant with text-block argument | `ALPHA("""x"""), BETA` | Yes | Each constant is emitted on its own line |
| Field dependencies | `B = A + 1` before `A = 0` | Yes | Respects dependency: A before B if B uses A |
| Multi-line initializers | Fields with anonymous class or lambda init | Yes | The declaration's full line span moves as a unit |
| Annotated fields | Fields with `@Deprecated` etc. above | Yes | Annotation lines move with their field |
| Nested generics in type | `Map<String, List<Integer>>` field | Yes | Reordered like any other type |
| Multi-line generic type | a generic type wrapped across lines (`Map<String,` / `Long> f;`) | Yes | The declaration's full line span moves as a unit |
| Circular dependencies | `A = B + 1; B = A + 1` | No | No order satisfies every dependency; the fixer returns a `SkipResult` (`cannot reorder fields with a circular dependency`) rather than emit a partial order |
| Anonymous class initializer | anon.class field must come before non-anon | Yes | Anon-class-init fields sort first within their chunk |
| Anon-class init with dependency | anon.class field references the field it must precede | No | The anon-first rule and the reference conflict; the fixer returns a documented `SkipResult` (`cannot reorder anonymous-class initializer field across a field it references`) |
| Multi-variable declaration with an interior comment | `String zebra, /* c */ alpha;` or a comment on a continuation line | No | Reordering the names would drop the comment; the fixer returns a `SkipResult` (`cannot reorder names in a multi-variable declaration containing a comment`) |
| Initialized multi-variable declaration | `int beta = 1, alpha = 2;` | No | Reordering initialized names is not a plain name list; the fixer returns a `SkipResult` (`cannot reorder initialized names in a multi-variable declaration`) |
| Multi-variable declaration with a C-style array declarator | `int y[], x;` | No | The name-only rebuild emits the shared type prefix plus the names, carrying no per-declarator suffix, so reordering would drop a declarator's own `[]` and silently retype it; the fixer returns a `SkipResult` (`a declarator carries its own C-style array brackets`) |
| Multi-variable secondary-name dependency | `int x, y, z;` then `int a = y + 1;` | No | The field's dependency resolves to a secondary name of a multi-var declaration, which can't be pinned by whole-line reordering; the fixer returns a `SkipResult` (`cannot reorder a field whose dependency is bound in a multi-variable declaration`) |
| Field ordered past a secondary name | `int alpha, zebra[];` then `int beta;` | No | The check orders declarators, the rebuild orders whole declarations, and consolidating the two would drop `zebra`'s `[]`; separating the secondary name needs a declaration split, so the fixer returns a `SkipResult` (`cannot reorder a field past a name bound in a multi-variable declaration`) |
| Same type, different modifiers | `int zebra;` then `private int alpha;` | Yes (reorder only) | Reordered but never consolidated: the merged declaration keeps one prefix, so merging would widen `alpha`'s visibility or drop a `transient`/`volatile` the check's rule does not look at |
| Wildcard bound annotations | `List<? extends @B Number>` before `List<? extends @A Number>` | Yes | Type-argument annotation ordering, position aware |
| Enum brace sharing a line with a constant | `enum E { ALPHA, BETA }`, `enum E {\n\tALPHA, BETA }`, `enum E { BETA,\n\tALPHA\n}` | Yes | Only the character span from just past the enum's `{` to its last constant is replaced, so the `enum E {` header and the closing `}` are re-emitted around the rebuilt constants. Constants that only ever shared the header line are indented one tab in from the enum's own line |
| Trailing comma before the closing brace | `enum E {\n\tA,\n\tB,\n}` | Yes | The span extends past the trailing `,`, and separators are re-applied from scratch, so the stray comma is absorbed rather than re-emitted |
| Comment between a constant's last token and its `,` | `ZETA /* t */,` | Yes | Kept as that constant's trailing comment, ahead of the re-applied separator |
| Comment after a `,` | `ZETA, /* mid */ ALPHA`, `ZETA, // t` | Yes | Belongs to the next constant when that constant shares the `,`'s line, otherwise to the constant the `,` terminates. Never emitted under both |
| Comment above the first constant | `enum E {\n\t// note\n\tZETA, ALPHA` | Yes | Travels with the constant that was first in source order; a comment on the header line itself stays on the header |
| Comment after the last constant | `\tALPHA\n\t// tail\n}` | Yes | Stays at the bottom, attached to no constant |
| Multi-line annotation whose first line is shared with the previous constant | `BETA, @SuppressWarnings(\n\t\t"x")\nALPHA` | Yes | The annotation is emitted from its own span, so the preceding constant is not duplicated into it |
| Two or more annotations on one constant | `@Deprecated @SuppressWarnings("x") ALPHA` | Yes | Each is emitted on its own line; a comment ahead of them is attributed once, to the first |
| Annotation whose argument is a string containing structural characters or spans lines | `@SuppressWarnings("{ } , // /*")` | Yes | Emitted verbatim from the span; string contents are never re-read as code |
| Blank line between constants | `enum E {\n\tZETA,\n\n\tALPHA\n}` | Yes (blank dropped) | Separators are re-applied from scratch and only non-blank trivia is carried, so a blank line between two constants does not survive the reorder. Its position after a sort is ambiguous (it separated the source pair, not the sorted one), so it is dropped rather than guessed at |
| Constant indented other than one tab in | `enum E {\n\t\t\tZETA,\n\t\t\tALPHA\n}` | Yes | The existing indent of the first constant that starts a line is reused for every emitted constant; the one-tab default applies only when no constant starts a line |
| Comment that does not close on the line it opens | `enum E { /*\n\tordinal order matters\n\t*/`, `ZETA, /* legacy;\n\tsee #123 */`, `ALPHA; /*\n\t*/` | No | The rebuild moves each constant together with the trivia it owns, so an opener on one side of an ownership boundary and its `*/` on the other would travel apart, commenting out whatever the sort moves between them; a header-line opener produces an enum that still compiles minus a constant. The fixer returns a `SkipResult` (`cannot reorder enum constants across a comment that does not close on the line it opens`). A comment opening in text that keeps its position (past the enum's closing brace, say) is not refused, since nothing moves across it |
| Comment trailing a constant across more than one line | `ZETA /* a */\n\t/* b */, ALPHA` | No | Trailing trivia rides on the re-applied separator line, so folding two lines into one would swallow everything after a `//`; the fixer returns a `SkipResult` (`cannot relocate a comment trailing an enum constant across multiple lines`) |
| Comment between a trailing `,` and the list terminator | `\tALPHA, // done\n\t;` | Yes | What shares the constant's own line is carried as that constant's trailing comment and moves with it |
| Comment on its own line between the last constant and the list terminator | `\tACTIVE,\n\t// NOTE: order matters\n\t;` | Yes | Treated as a note about the list rather than about whichever constant happened to be last in source order, so it is re-emitted after the sorted constants instead of travelling with one of them. Applies whether or not the last constant carries a trailing comma. Only the tail's first line is re-indented; a block comment spanning lines keeps its interior alignment and its blank lines |
| Member sharing the constant-list terminator line | `\tALPHA; static final int VAL = 1;` | Yes | The member is re-emitted on its own line at the constant indent, or at the enum's own indent when it starts with `}`. A member that opens a text block or a block comment there is re-emitted the same way: only its opening line moves, and the lines it spans keep their position, so the literal's content is unchanged. A comment-only tail that opens such a literal is refused instead, because that tail is folded into the last constant and would travel with it |
| Comment between an annotation and its constant, or between two annotations | `@Deprecated\n\t// note\n\tALPHA`, `@Deprecated /* x */ @SuppressWarnings("y")` | Yes | Emitted in place within the constant's own leading block, which moves as one unit |
| Multi-line text block in a constant argument | `ZETA("""\n\t\tx\n\t\t""")` | Yes | Only the constant's first line is re-indented; the block's content lines and closing delimiter are emitted byte-verbatim |
| Annotated static field group | `@SuppressWarnings("unused") static String beta;` then `@Deprecated static String alpha;` | No | The modifier/annotation interplay across a static group cannot be reproduced faithfully by the rebuild; the fixer returns a `SkipResult` (`cannot safely reorder static fields with annotations`) |
| Enum-constant body | fields inside `INSTANCE { ... }` | Yes | Sorted like any other class body. Constructor arguments on the constant, a comment on the body opener, and a text-block initializer inside the body all survive the rebuild |
